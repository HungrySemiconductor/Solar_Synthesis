# 无需修改 Surya 原始数据集的训练策略

> **核心问题**：Surya 训练数据约 257TB（2011-2019 SDO 全分辨率观测），无法下载。所有 SDO 图像均来自约 1 AU 的地球轨道位置，不存在多视角真值。如何在不修改/不下载原始数据集的前提下，训练轨道条件化模块？

---

## 一、为什么不需要全量数据集

### 1.1 你是微调，不是从头训练

| | Surya 预训练 | 你的轨道条件微调 |
|---|---|---|
| 参数量 | 366M（全部） | ~44M（12%，仅条件模块） |
| 数据量 | 257TB | ~10-100 GB 足够 |
| 训练目标 | 学习太阳物理表征 | 学习"已知表征"的视角变换 |
| 训练步数 | 160K steps × 128 GPU | 5K-20K steps × 1 GPU |
| 可用的预训练知识 | — | 冻结 Encoder 已编码全部太阳物理特征 |

**关键认知**：冻结的 Surya Encoder 已经"理解"了太阳——活动区、冕洞、耀斑、磁场结构。你只需要教会条件模块说"从侧面看，这个活动区应该长这样"，而不是重新学习什么叫活动区。

### 1.2 需要的最小数据量

```
Surya 测试代码（test_surya.py:66-72）只用 8 个 NetCDF 文件验证模型。
Surya 下游任务（downstream_examples/）用小的子集做微调。
Surya 数据可通过 AWS S3 按需下载单个文件（run_easy_inference.py:582-611）。
```

**实际需求估算**：

- 最小实验：1 天 × 12 分钟采样 = 120 个文件 ≈ 5 GB
- 稳定训练：7 天 × 12 分钟采样 = 840 个文件 ≈ 35 GB
- 完整训练：30 天 × 12 分钟采样 = 3600 个文件 ≈ 150 GB

---

## 二、核心认知：这不是监督学习，而是条件映射学习

你的真实训练场景是：

```
输入：SDO 图像（来自 1 AU）+ 目标轨道参数（来自 SPO 轨迹）
期望输出：从 SPO 位置看到的太阳图像

但你没有 SPO 位置的真值图像！
```

**这意味着你需要创造性地构建训练信号**。以下是三种实际可行的训练范式。

---

## 三、策略 A：几何自监督（推荐起步，最快出结果）

### 核心思想

用你的 `single_scale.py` 中的几何缩放作为"伪真值"训练信号。模型学习：
- 给定任意距离 → 产生正确的太阳视直径
- 几何缩放是确定性的（$r_1/r_2$），可以作为强监督

### 训练流程

```
Step 1: 加载 SDO 图像 I_1AU（来自 1 AU 位置 P_src）
Step 2: 随机采样一个"虚拟目标距离" d_tgt
Step 3: 用 single_scale.py 逻辑生成几何缩放图 I_geo = scale(I_1AU, 1AU/d_tgt)
Step 4: 模型输入 = (I_1AU, P_src, P_tgt)
        模型预测 = I_pred
        损失 = MSE(I_pred, I_geo)
```

### 代码实现（自定义 Dataset）

```python
class OrbitAugmentedDataset(Dataset):
    """
    基于少量 SDO 文件 + 轨道参数增强的数据集。
    不修改原始 NC 文件，所有增强在 DataLoader 中 on-the-fly 完成。
    """
    def __init__(
        self,
        nc_files: list[str],          # 少量 SDO 文件路径
        reference_orbit: tuple,       # SDO 的标准轨道 (1 AU 位置)
        target_orbit_csv: str,        # SPO 轨道 CSV
        scalers: dict,
        channels: list[str],
        pooling: int = 1,
    ):
        self.nc_files = nc_files
        self.reference_orbit = np.array(reference_orbit)  # [x, y, z, vx, vy, vz]
        self.target_orbits = pd.read_csv(target_orbit_csv)
        self.scalers = scalers
        self.channels = channels
        self.pooling = pooling
    
    def __len__(self):
        return len(self.nc_files) * len(self.target_orbits)
    
    def __getitem__(self, idx):
        file_idx = idx // len(self.target_orbits)
        orbit_idx = idx % len(self.target_orbits)
        
        # 1. 加载 SDO 图像（1 AU）
        image_1au = self._load_and_transform(self.nc_files[file_idx])
        # shape: (C, H, W)
        
        # 2. 获取目标轨道参数
        orbit_row = self.target_orbits.iloc[orbit_idx]
        target_position = np.array([
            orbit_row['x_km'], orbit_row['y_km'], orbit_row['z_km'],
            orbit_row['vx_kms'], orbit_row['vy_kms'], orbit_row['vz_kms']
        ], dtype=np.float32)
        
        # 3. 归一化轨道参数
        target_orbit = self._normalize_orbit(target_position)
        source_orbit = self._normalize_orbit(self.reference_orbit)
        
        # 4. 计算距离比
        r_src = np.linalg.norm(target_position[:3])  # km
        r_tgt = np.linalg.norm(self.reference_orbit[:3])  # km
        scale_factor = r_src / r_tgt
        
        # 5. 生成几何缩放的目标图像（伪真值）
        image_geo = self._geometric_scale(image_1au, scale_factor)
        
        # 6. 构建模型输入
        # 模拟时间序列输入：将单张图复制为 2 个时间步
        ts = np.stack([image_1au, image_1au], axis=1)  # (C, 2, H, W)
        
        return {
            "ts": ts.astype(np.float32),
            "time_delta_input": np.array([0.0, 0.2], dtype=np.float32),  # 12分钟间隔
            "orbit_params": source_orbit.astype(np.float32),  # B, 6
            "forecast": image_geo[np.newaxis, ...],            # (C, 1, H, W) — 目标
        }, {
            "scale_factor": scale_factor,
            "target_orbit": target_orbit,
        }
    
    def _normalize_orbit(self, orbit_6d):
        """归一化：位置/1AU, 速度/29.8 km/s"""
        normalized = orbit_6d.copy()
        normalized[:3] = normalized[:3] / 149597870.7
        normalized[3:] = normalized[3:] / 29.8
        return normalized
    
    def _geometric_scale(self, image, scale_factor):
        """调用 single_scale.py 的缩放逻辑"""
        C, H, W = image.shape
        scaled = np.zeros_like(image)
        for c in range(C):
            scaled[c] = scale_single_channel(image[c], scale_factor)
        return scaled
```

### 这个策略的优缺点

| 优点 | 缺点 |
|------|------|
| 只需要少量 SDO 文件（几十个即可） | 无法学习真实纹理变化 |
| 距离变化可以精确学习 | 所有"伪真值"都是纯几何变换 |
| 不需要修改任何 Surya 代码 | 方位（视角）变化无法通过此方法学习 |
| 立即可行 | 模型可能只学会几何缩放而忽略轨道编码器 |

## 四、策略 B：物理一致性约束（无需配对数据）

### 核心思想

利用太阳物理的先验知识作为无监督损失函数。这些损失不需要"真值图像"，只需要"合理的物理约束"。

### 物理约束类型

#### 约束 1：总辐射通量守恒（Flux Conservation）

无论从哪个距离观测，太阳的总 EUV 辐射通量（修正距离后）应该守恒：

```python
def flux_conservation_loss(pred, source, r_src, r_tgt):
    """
    pred: (B, C, H, W) — 目标位置预测
    source: (B, C, H, W) — 源位置图像
    r_src: (B,) — 源距离
    r_tgt: (B,) — 目标距离
    
    原理：总通量应满足 F_tgt / F_src = (r_src / r_tgt)²
    """
    # 计算太阳圆面区域（简单阈值法）
    sun_mask_src = (source > source.mean(dim=(-2,-1), keepdim=True) * 0.1).float()
    sun_mask_tgt = (pred > pred.mean(dim=(-2,-1), keepdim=True) * 0.1).float()
    
    flux_src = (source * sun_mask_src).sum(dim=(-2, -1))  # B, C
    flux_tgt = (pred * sun_mask_tgt).sum(dim=(-2, -1))    # B, C
    
    expected_ratio = (r_src / r_tgt) ** 2  # 距离修正
    actual_ratio = flux_tgt / (flux_src + 1e-8)
    
    return F.mse_loss(actual_ratio, expected_ratio.unsqueeze(1))
```

#### 约束 2：太阳自转周期一致性（Solar Rotation Consistency）

太阳每 ~27 天自转一周。两张相隔 13.5 天的 SDO 图像看到的是太阳的"背面"关系。相隔 27 天的图像看到几乎相同的面。

```python
def rotation_consistency_loss(pred, source_image_27days_later, orbit_27days_later):
    """
    如果模型从源图像 + 27天后轨道 → 生成图像，
    则生成的图像应与 27 天后的真实 SDO 图像相似
    （因为太阳自转回相同的面）
    """
    return F.mse_loss(pred, source_image_27days_later)
```

这可以利用 SDO 自身数据的时序规律，提供真实的纹理监督信号。

#### 约束 3：边缘临边昏暗梯度（Limb Darkening Gradient）

太阳边缘比中心暗（临边昏暗效应）。从不同角度观测，临边昏暗的模式应该不同：

```python
def limb_darkening_gradient_loss(pred):
    """
    鼓励生成的图像在太阳边缘有合理的亮度梯度。
    使用 Sobel 算子检测径向梯度模式。
    """
    # 计算图像的径向梯度
    B, C, H, W = pred.shape
    y, x = torch.meshgrid(
        torch.linspace(-1, 1, H, device=pred.device),
        torch.linspace(-1, 1, W, device=pred.device),
        indexing='ij'
    )
    r = torch.sqrt(x**2 + y**2)  # H, W
    
    # 太阳边缘（r > 0.85）处的梯度应该向内
    edge_mask = (r > 0.85) & (r < 1.0)
    sobel_x = F.conv2d(pred, sobel_x_kernel, padding=1)
    sobel_y = F.conv2d(pred, sobel_y_kernel, padding=1)
    grad_mag = torch.sqrt(sobel_x**2 + sobel_y**2)
    
    # 边缘处应该有显著但不过度的梯度
    edge_gradient = grad_mag * edge_mask.float()
    return edge_gradient.mean()  # 惩罚过平或过激的边缘
```

#### 约束 4：特征结构保持（Feature Structure Preservation）

太阳的特征（活动区、冕洞）在短时间尺度上保持结构稳定：

```python
def structure_preservation_loss(pred, source, window_size=7):
    """
    局部结构相似性约束。
    使用 SSIM 或局部归一化互相关。
    """
    # 降采样后比较结构（容忍尺度和位移变化）
    pred_down = F.avg_pool2d(pred, window_size)
    src_down = F.avg_pool2d(source, window_size)
    
    # 归一化互相关
    pred_norm = (pred_down - pred_down.mean()) / (pred_down.std() + 1e-8)
    src_norm = (src_down - src_down.mean()) / (src_down.std() + 1e-8)
    
    return 1.0 - (pred_norm * src_norm).mean()
```

### 物理约束训练的总损失

```python
total_loss = (
    1.0 * geometric_mse_loss +          # 策略A的监督信号
    0.1 * flux_conservation_loss +      # 通量守恒
    0.05 * limb_darkening_gradient_loss + # 临边昏暗
    0.2 * structure_preservation_loss + # 结构保持
    0.1 * rotation_consistency_loss     # 自转一致性（如有数据）
)
```

这个方案的关键优势：**flux_conservation_loss 和 limb_darkening_loss 完全不需要地面真值**，只需要模型预测和物理公式。

## 五、策略 C：循环一致性（Cycle Consistency）

### 核心思想

如果模型能 SDO位置 → SPO位置，那它也应该能 SPO位置 → SDO位置。两次变换后应该回到原图。

```
I_sdo ──[orbit: SDO→SPO]──→ I_spo_pred ──[orbit: SPO→SDO]──→ I_sdo_reconstructed
                                                                      │
                                                          loss = MSE(I_sdo, I_sdo_reconstructed)
```

### 实现

```python
def cycle_consistency_loss(model, sdo_image, sdo_orbit, spo_orbit):
    """
    前向：SDO图像 + SPO轨道 → SPO视角预测
    反向：SPO预测 + SDO轨道 → SDO视角重建
    损失：原始SDO图像 vs 重建SDO图像
    """
    # 前向映射：1 AU → SPO 位置
    batch_forward = {
        "ts": sdo_image,
        "time_delta_input": dt,
        "orbit_params": spo_orbit,       # 目标轨道 = SPO
    }
    spo_pred = model(batch_forward)      # 模型生成 SPO 视角图像
    
    # 反向映射：SPO 位置 → 1 AU
    batch_backward = {
        "ts": spo_pred.unsqueeze(2),     # 用预测作为"源"
        "time_delta_input": dt,
        "orbit_params": sdo_orbit,       # 目标轨道 = SDO
    }
    sdo_reconstructed = model(batch_backward)
    
    # 循环一致性损失
    return F.mse_loss(sdo_reconstructed, sdo_image)
```

**但这有一个问题**：反向映射时，模型输入已经变成了模型生成的 SPO 图像（可能质量不好），这会导致训练不稳定。

### 改进：感知循环一致性

不使用像素级 MSE，而是使用冻结的 Surya Encoder 的表征空间：

```python
def perceptual_cycle_consistency_loss(model, frozen_encoder, sdo_image, sdo_orbit, spo_orbit):
    # 在冻结 Encoder 的特征空间中比较
    with torch.no_grad():
        sdo_features = frozen_encoder(sdo_image)  # Surya backbone 的输出
    
    spo_pred = model(...)
    sdo_reconstructed = model(..., spo_pred, sdo_orbit)
    
    sdo_recon_features = frozen_encoder(sdo_reconstructed)
    
    return F.mse_loss(sdo_recon_features, sdo_features)
```

## 六、策略 D：利用地球轨道自然变化（最优长期方案）

### 核心发现：SDO 数据本身就有轨道多样性

SDO 卫星在地球同步轨道，但地球绕太阳的轨道并非正圆：

```
地球轨道偏心率：0.0167
距离变化范围：0.983 AU ~ 1.017 AU (±1.7%)
一年内 SDO 视直径变化：约 ±1.7%
SDO 的位置在一年中有约 5,000,000 km 的变化
```

**这意味着 Surya 的 2011-2019 年训练数据本身就包含了不同轨道位置的太阳图像！**

SDO 轨道的 `(x, y, z)` 随时间变化（随地球公转），虽然变化幅度不大，但足以提供初始训练信号。

### 具体做法

```python
# 对于 Surya 数据集中的每个时间戳，计算当时的地球/SDO 位置
from astropy.coordinates import get_body_barycentric
from astropy.time import Time

def get_earth_position(timestamp):
    """获取给定时间戳的地球日心坐标"""
    t = Time(timestamp)
    pos = get_body_barycentric('earth', t)
    return np.array([pos.x.value, pos.y.value, pos.z.value])  # km

# 在 DataLoader 中使用真实的地球位置作为轨道条件
# 训练时：输入 = 真实 SDO 图像，条件 = 真实地球位置
# 测试时：输入 = SDO 图像，条件 = SPO 位置 → 模型外推到新视角
```

**配合策略 A 的几何增强**，可以大幅扩展有效距离范围：

```python
# 训练循环中
earth_orbit = get_earth_position(timestamp)       # 真实值：~1 AU
augmented_orbit = random_augment_orbit(earth_orbit) # 增强值：0.3~3.2 AU

# 真实距离训练（学会 Earth 的自然变化）
loss_real = train_step(model, sdo_image, earth_orbit)     

# 增强距离训练（学会大幅度的几何缩放）
loss_augmented = train_step(model, geometrically_scaled_image, augmented_orbit)

total_loss = loss_real + 0.5 * loss_augmented
```

## 七、综合推荐方案

### 数据准备（最小集合）

```
1. 从 S3 下载 3-7 天 SDO 数据（每天 120 个文件 × 7 = 840 个文件 ≈ 35 GB）
   命令：aws s3 cp s3://nasa-surya-bench/2014/01/ ./data/ --recursive --no-sign-request

2. 用 astropy 计算每个时间戳的地球位置（几行代码）

3. 准备 SPO 轨道 CSV（你已有的 batch_scale.py 处理的轨迹数据）

4. No 需要下载、修改或预处理 Surya 的原始 257TB 数据集
```

### 三阶段训练方案

```
阶段 1：几何预热（3-5 epochs, ~2000 steps）
  ├── 训练：Orbit Encoder + OrbitFlow(距离缩放)
  ├── 损失：纯几何 MSE（策略 A）
  ├── 数据：1 天 SDO + 随机增强距离
  ├── 目标：学会 1/r 几何缩放
  └── 预期 loss：快速下降并收敛

阶段 2：纹理学习（5-10 epochs, ~5000 steps）
  ├── 训练：Orbit Encoder + adaLN 调制层 + LoRA(Attention)
  ├── 损失：几何 MSE + 物理约束（策略 A + B）
  ├── 数据：7 天 SDO + 真实地球轨道 + 增强轨道
  ├── 目标：学会视角相关的纹理变化
  └── 预期 loss：缓慢下降

阶段 3：精调（3-5 epochs, ~2000 steps）
  ├── 训练：全部条件模块 + 低学习率微调 Decoder
  ├── 损失：几何 MSE + 物理约束 + 循环一致性（策略 A + B + C）
  ├── 数据：30 天 SDO（如需更好泛化）
  └── 预期 loss：微幅下降
```

## 八、关键代码：最小可行的 Dataset

```python
import torch
from torch.utils.data import Dataset
import numpy as np
import xarray as xr
from astropy.time import Time
from astropy.coordinates import get_body_barycentric
import astropy.units as u

class MinimalOrbitDataset(Dataset):
    """
    最小化数据集：基于少量 SDO 文件 + on-the-fly 轨道增强。
    完全不修改 Surya 原始数据。
    """
    
    def __init__(
        self,
        nc_file_paths: list[str],          # 几十到几百个 NC 文件路径
        spo_orbit_df,                       # SPO 轨道 DataFrame
        scalers: dict,
        channels: list[str],
        use_augmentation: bool = True,
        aug_distance_range: tuple = (0.3, 3.2),  # AU 范围
    ):
        self.nc_files = nc_file_paths
        self.spo_orbits = spo_orbit_df
        self.scalers = scalers
        self.channels = channels
        self.use_augmentation = use_augmentation
        self.aug_range = aug_distance_range
        
        # 缓存：每个 NC 文件对应的地球位置
        self._earth_positions = {}
    
    def __len__(self):
        return len(self.nc_files)
    
    def _get_earth_position(self, timestamp_str) -> np.ndarray:
        """获取 SDO/地球 在给定时刻的日心坐标 (km)"""
        if timestamp_str in self._earth_positions:
            return self._earth_positions[timestamp_str]
        
        t = Time(timestamp_str)
        pos = get_body_barycentric('earth', t)
        # 转为 km
        x = pos.x.to(u.km).value
        y = pos.y.to(u.km).value
        z = pos.z.to(u.km).value
        
        # SDO 的速度（地球公转速度矢量，近似）
        # 更精确的做法是用两个邻近时刻计算差分
        earth_pos = np.array([x, y, z], dtype=np.float32)
        self._earth_positions[timestamp_str] = earth_pos
        return earth_pos
    
    def _normalize_orbit(self, pos_3d: np.ndarray) -> np.ndarray:
        """位置归一化到 [0,~3.2] AU 范围"""
        return pos_3d / 149597870.7  # 1 AU in km
    
    def __getitem__(self, idx):
        # 1. 加载 SDO 图像
        filepath = self.nc_files[idx]
        with xr.open_dataset(filepath, engine="h5netcdf") as ds:
            data = ds[self.channels].to_array().load().to_numpy()
        # data: (C, H, W)
        
        # 2. 应用 signum-log 变换（与 Surya 训练一致）
        # （具体实现见 helio.py:59-89）
        data_transformed = self._signum_log_transform(data)
        # data_transformed: (C, H, W), float32
        
        # 3. 获取源轨道（真实地球位置）
        # 从文件名或元数据中提取时间戳
        timestamp = self._extract_timestamp_from_filename(filepath)
        earth_pos_3d = self._get_earth_position(timestamp)
        earth_vel_3d = self._estimate_velocity(timestamp, earth_pos_3d)
        source_orbit = np.concatenate([
            self._normalize_orbit(earth_pos_3d),
            earth_vel_3d / 29.8  # 归一化速度
        ]).astype(np.float32)  # (6,)
        
        # 4. 获取目标轨道（从 SPO 轨迹中随机采样，或使用增强距离）
        if self.use_augmentation:
            # 随机生成虚拟观测距离
            aug_au = np.random.uniform(*self.aug_range)  # 0.3 ~ 3.2 AU
            # 保持方向，改变距离
            earth_dir = earth_pos_3d / np.linalg.norm(earth_pos_3d)
            target_pos_3d = earth_dir * (aug_au * 149597870.7)
            target_orbit = np.concatenate([
                self._normalize_orbit(target_pos_3d),
                np.zeros(3, dtype=np.float32)  # 简化：假设速度为零
            ]).astype(np.float32)
        else:
            # 使用 SPO 轨道的真实采样
            row = self.spo_orbits.sample(1).iloc[0]
            target_pos_3d = np.array([row['x_km'], row['y_km'], row['z_km']])
            target_orbit = np.concatenate([
                self._normalize_orbit(target_pos_3d),
                np.array([row['vx_kms'], row['vy_kms'], row['vz_kms']]) / 29.8
            ]).astype(np.float32)
        
        # 5. 生成几何缩放的目标（伪真值）
        r_src = np.linalg.norm(earth_pos_3d)  # km
        r_tgt = np.linalg.norm(target_pos_3d)  # km
        scale_factor = r_src / r_tgt
        
        data_geo = self._geometric_scale(data_transformed, scale_factor)
        
        # 6. 构建时间序列输入（单图复制为 2 步）
        ts = np.stack([data_transformed, data_transformed], axis=1)  # (C, 2, H, W)
        
        return {
            "ts": ts,
            "time_delta_input": np.array([-0.2, 0.0], dtype=np.float32),
            "orbit_params": source_orbit,
            "forecast": data_geo[np.newaxis, ...],  # (C, 1, H, W)
            "target_orbit_params": target_orbit,
        }, {
            "timestamp": timestamp,
            "source_orbit": source_orbit,
            "target_orbit": target_orbit,
            "scale_factor": scale_factor,
        }
```

## 九、总结

| 你的顾虑 | 实际情况 |
|----------|----------|
| "需要修改 Surya 原始数据集" | ❌ 不需要。所有增强在 DataLoader 中 on-the-fly 完成 |
| "需要下载 257TB 数据" | ❌ 不需要。3-7 天的数据（5-35 GB）足够微调 |
| "没有多视角真值图像" | ✅ 确实没有。但通过几何增强 + 物理约束 + 循环一致性能有效训练 |
| "SPO 轨迹和 SDO 轨迹不同" | ✅ 这正是条件模块要学习的——将 SDO 视角映射到 SPO 视角 |

**核心方法论**：你不是在做"有监督的图像翻译"（那确实需要配对数据），而是在做**"物理约束的条件生成"**——利用：
1. 确定性几何缩放（策略 A）作为强监督
2. 物理守恒定律（策略 B）作为弱监督
3. 循环一致性（策略 C）作为自监督
4. 地球轨道自然变化（策略 D）提供真实视角多样性

四种策略的组合可以在**不需要任何非地球视角真值**的前提下，训练出有效的轨道条件化模型。
