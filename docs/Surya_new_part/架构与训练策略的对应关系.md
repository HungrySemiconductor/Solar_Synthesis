# 架构与训练策略的对应关系

> 回答的核心问题：如果按照"几何与物理约束的架构解耦"来设计架构，是否能够使用"无需原始数据集的训练策略"中的方法步骤？两者是否兼容？

---

## 两份文档的定位

| | 无需原始数据集的训练策略 | 几何与物理约束的架构解耦 |
|---|---|---|
| **回答的问题** | "没有 SPO 真值图像，怎么训练？" | "先几何后纹理，会不会冲突？" |
| **关注点** | 训练数据从哪来、损失信号怎么构造 | 架构内部梯度流、模块解耦 |
| **视角** | 外部（数据 + 损失函数） | 内部（网络层 + 参数更新） |

它们是从**同一个架构的两个视角**来描述同一件事。

---

## 架构视角 vs 训练策略视角的对应关系

Surya 数据流：

```
输入 (B,C,T,H,W) → Embedding → Backbone → Decoder → 输出 (B,C,H,W)
                   (冻结)      (冻结)     (训练)
```

两份文档描述的是**同一个修改架构**，只是用了不同语言：

| 架构解耦文档的描述 | 训练策略文档的描述 | 对应 |
|---|---|---|
| ① OrbitAwareFlowModel（像素层） | 策略 A：几何缩放伪真值 | 距离 → 太阳大小 |
| ④ adaLN 调制（特征层，BlockAttention 内部） | 策略 B：物理约束损失 | 方位 → 纹理变化 |
| — | 策略 C：循环一致性 | 验证生成一致性 |
| — | 策略 D：地球轨道自然变化 | 利用 SDO 自身视角多样性 |

**关键点**：策略文档中的四种训练信号（A/B/C/D）分别驱动架构文档中的不同模块，互不干扰。

---

## 两者结合后的训练全貌

以下是把两份文档的内容合并成一个完整、可执行的训练流程。

### 阶段 1：几何（策略 A 驱动 OrbitAwareFlowModel）

```
冻结: Embedding, Backbone(含adaLN)
训练: OrbitAwareFlowModel + Decoder
数据: SDO图像 + 随机生成的目标距离
损失: L_geo = MSE(模型输出, 几何缩放伪真值)
```

```python
for epoch in range(5):
    for batch in dataloader:
        # batch 包含:
        #   ts:     SDO 图像序列 (B, C, 2, 4096, 4096)
        #   orbit_params: 源轨道 + 目标轨道 (B, 6)

        pred = model(batch)             # 经过 ①FlowModel + ②Embedding(冻结)
                                        # + ③Backbone(冻结,adaLN不工作)
                                        # + ⑤Decoder(训练)

        gt_geo = geometric_scale(        # 用你的 single_scale.py 逻辑
            batch["ts"], scale_factor    # 生成几何缩放的"伪真值"
        )

        loss = MSE(pred, gt_geo)         # 只有几何监督
        loss.backward()                  # 梯度只更新 FlowModel + Decoder
        optimizer.step()
```

### 阶段 2：纹理（策略 B 驱动 adaLN + LoRA）

```
保持冻结: Embedding, OrbitAwareFlowModel ← 注意FlowModel也冻结了!
解冻训练: adaLN(8层调制器) + LoRA(Attention权重) + Decoder
数据: 同阶段1，但增加了真实轨道参数
损失: L_geo(保留,防止遗忘) + L_flux + L_limb + L_struct
```

```python
for epoch in range(10):
    for batch in dataloader:
        pred = model(batch)             # 经过 ①FlowModel(冻结,detach)
                                        # + ②Embedding(冻结)
                                        # + ③Backbone(adaLN训练,LoRA训练)
                                        # + ⑤Decoder(训练)

        # 几何监督（保留，权重0.5，防止遗忘）
        loss_geo = MSE(pred, gt_geo)

        # 物理约束监督（新增，完全不需要真值图像）
        loss_flux = flux_conservation(pred, source, r_src, r_tgt)
        loss_limb = limb_darkening(pred)
        loss_struct = structure_preservation(pred, source)

        total_loss = 0.5*loss_geo + 0.1*loss_flux + 0.05*loss_limb + 0.1*loss_struct
        total_loss.backward()           # 梯度主要更新 adaLN + LoRA
        optimizer.step()
```

## 为什么两者完全兼容

### 1. 模块冻结/解冻与 Shape 无关

不管你冻结还是训练哪个模块，Shape 变化路径完全不变：

```
(B,C,T,H,W) → (B,L,D) → (B,L,D) → (B,C,H,W)
 ↑                          ↑           ↑
 FlowModel              adaLN注入    Decoder
 (阶段1训练,阶段2冻结)   (阶段2训练)  (两个阶段都训练)
```

模块的 freeze/unfreeze 只影响**梯度是否回传到这个模块的参数**，不影响数据能否流过。所以任何时候加新损失项都不会"堵住"数据流。

### 2. 损失项只看最终输出

所有损失（`L_geo`, `L_flux`, `L_limb`, `L_struct`）都只读取模型的**最终输出** `pred = (B, C, H, W)`：

```
pred  ←  这是模型唯一的输出
  │
  ├── L_geo   = MSE(pred, geometric_gt)      ← 需要伪真值
  ├── L_flux  = flux_loss(pred, source)       ← 不需要任何真值
  ├── L_limb  = limb_loss(pred)               ← 不需要任何真值
  └── L_struct = struct_loss(pred, source)    ← 不需要任何真值
```

它们之间唯一的交互是**梯度加和**（`total_loss = w1*L1 + w2*L2 + ...`），PyTorch 的 `backward()` 会自动处理，你不需要做任何额外工作。

### 3. 阶段过渡只需要保存/加载 checkpoint

```python
# 阶段1结束
torch.save(model.state_dict(), "phase1_geometry.pt")

# 阶段2开始
model.load_state_dict(torch.load("phase1_geometry.pt"))
# 然后改变 freeze/unfreeze 的设置
# 继续训练
```

不需要改模型结构，不需要改数据管道，只是改哪些参数需要梯度。

---

## 总结

> **完全可以。两份文档描述的是同一架构的两个视角——解耦文档确保梯度不冲突，策略文档提供训练信号来源。两者配合：策略 A 驱动 FlowModel（阶段1），策略 B 驱动 adaLN（阶段2），两个阶段用同一个模型、同一个数据管道、只是 freeze/unfreeze 的设置不同。**

如果你对数据流（`(B,C,T,H,W)→Embedding→Backbone→Decoder→(B,C,H,W)`）已经完全理解了，这个架构上的任何修改都只是在特定的模块上"挂接"新的输入或损失。你已经具备了评估这些修改是否合理的基础。
