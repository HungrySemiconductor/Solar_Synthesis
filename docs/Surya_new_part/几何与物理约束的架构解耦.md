# 几何变化与物理约束的架构解耦分析

> 核心问题：先实现几何缩放，后添加物理纹理约束，两者是否冲突？架构是否支持渐进式构建？

---

## 一、直接回答：两者完全解耦，不会冲突

几何缩放和纹理约束在架构中作用于**不同的层级、使用不同的机制、通过不同的损失项进行优化**。先实现几何不影响后续添加纹理约束。

关键原因：**它们操作在不同的网络深度**。

---

## 二、数据流中的位置对比

```
输入图像 (B,C,T,H,W)
    │
    ├─ ① 几何缩放层 (OrbitAwareFlowModel)
    │     └─ F.grid_sample + 距离感知 scale
    │     └─ 作用范围：像素空间
    │     └─ 参数：~20K
    │     └─ 输出：已缩放的图像 (B,C,T,H,W)
    │
    ▼
    ├─ ② Embedding (冻结)
    │     └─ PatchEmbed3D + Position Encoding
    │     └─ 像素 → Token
    │
    ▼
    ├─ ③ Backbone / SpectFormer (冻结 + LoRA)
    │     ├─ BlockSpectralGating ×2 (频域)
    │     └─ BlockAttention ×8
    │           └─ ④ adaLN 调制 (纹理条件注入)
    │                 └─ orbit_embed → shift/scale/gate × 6
    │                 └─ 作用范围：特征空间
    │                 └─ 参数：~28M
    │
    ▼
    ├─ ⑤ Decoder (可训练)
    │     └─ Token → 像素
    │
    ▼
输出图像 (B,C,H,W)
    │
    └─ ⑥ 损失计算
          ├─ L_geo:   MSE(pred, geo_scaled_gt)     ← 策略 A
          ├─ L_flux:  flux_conservation(pred, src)  ← 策略 B
          ├─ L_limb:  limb_darkening_gradient(pred) ← 策略 B
          └─ L_struct: structure_preservation(pred) ← 策略 B
```

**关键点**：几何缩放（①）发生在 Embedding 之前，纹理调制（④）发生在 Backbone 内部，损失（⑥）发生在最终输出。三者在不同阶段，互不干扰。

---

## 三、为什么先几何后纹理不会产生冲突

### 3.1 梯度流独立

```
L_geo 的梯度流向：
  ⑥ → ⑤(Decoder) → ③(Backbone) → ②(Embedding) → ①(FlowModel)
  
  L_geo 主要更新的参数：FlowModel 的 scale 和 flow_generator

L_phys（物理约束）的梯度流向：
  ⑥ → ⑤(Decoder) → ③(Backbone) → ②(Embedding)
  
  L_phys 主要更新的参数：adaLN 调制层 + LoRA attention 权重
```

两者的梯度路径有重叠（都经过 Backbone），但各自的损失函数驱动不同参数组的更新：

| 损失 | 主要驱动参数 | 物理含义 |
|------|-------------|----------|
| `L_geo` | FlowModel.scale, FlowModel.flow_generator | "距离越远，太阳越小" |
| `L_flux` | adaLN_modulation (gate 参数) | "总辐射能量守恒" |
| `L_limb` | adaLN_modulation (shift 参数) | "边缘应该比中心暗" |
| `L_struct` | LoRA attention 权重 | "活动区形状可变形但不应该消失" |

### 3.2 具体验证：先训练几何，再添加纹理

```python
# ===================================================
# 阶段 1：仅几何缩放（训练 3-5 epochs）
# ===================================================
model = HelioSpectFormer(use_orbit_condition=True)
# 冻结：embedding, backbone (incl. adaLN), 原始 decoder
freeze(model.embedding)
freeze(model.backbone)
# 训练：OrbitFlowModel + 新 decoder
trainable = [model.orbit_flow.parameters(), model.unembed.parameters()]

loss = MSE(pred, geometric_gt)  # 纯几何监督

# 训练完成后保存 checkpoint
save_checkpoint(model, "phase1_geometry.pt")

# ===================================================
# 阶段 2：添加物理纹理约束（训练 5-10 epochs）
# 加载阶段 1 的权重，在此基础上继续
# ===================================================
model = HelioSpectFormer(use_orbit_condition=True)
load_checkpoint(model, "phase1_geometry.pt")  # ← 几何能力保留

# 解冻 adaLN + 添加 LoRA
unfreeze(model.backbone.blocks_attention[*].adaLN_modulation)
add_lora(model.backbone.blocks_attention, rank=32)

loss = (
    0.5 * MSE(pred, geometric_gt) +       # 继续用几何监督，防止遗忘
    0.1 * flux_conservation_loss(pred) +  # 新添加：物理约束
    0.05 * limb_darkening_loss(pred) +    # 新添加：物理约束
    0.1 * structure_preservation_loss(pred) # 新添加：物理约束
)
# 阶段 1 学会的几何缩放不会退化，因为 L_geo 仍在 loss 中
```

**为什么不会退化**：`L_geo` 保留在总损失中，持续对 FlowModel 施加约束。即使新的物理损失项有不同梯度方向，`L_geo` 的权重更大（0.5 vs 0.05~0.1），几何能力会被保留。

## 四、架构层面的防冲突设计

### 4.1 FlowModel 和 adaLN 的独立性

```python
# helio_spectformer.py forward 中的关键代码结构

def forward(self, batch):
    x = batch["ts"]                              # 原始像素
    
    # === 阶段 1 关注的代码（几何）===
    if self.use_orbit_flow:
        x_flow = self.orbit_flow(batch)          # B, C, H, W
        x = torch.concat((x, x_flow.unsqueeze(2)), dim=2)
        # ↑ 仅影响输入像素空间，之后不再改动
    # =================================
    
    # === Embedding（冻结，两个阶段一致）===
    tokens = self.embedding(x, dt)
    
    # === 阶段 2 关注的代码（纹理）===
    #     orbit_embed 通过 adaLN 注入 Attention 层
    tokens = self.backbone(tokens, condition=orbit_embed)
    # =================================
    
    # === Decoder ===
    forecast = self.unembed(tokens)
    
    return forecast
```

几何变换（`orbit_flow`）和纹理调制（`condition=orbit_embed`）是两条**并行且独立**的路径，都接收 `orbit_params` 作为输入，但作用于网络的不同深度。

### 4.2 梯度隔离实验

如果想确保两个阶段完全独立，可以在阶段 2 训练时对几何模块使用 `detach()`：

```python
# 阶段 2 的 forward 中（可选）
def forward_phase2(self, batch):
    x = batch["ts"]
    
    # 几何缩放（冻结，不接收梯度）
    with torch.no_grad():
        x_flow = self.orbit_flow(batch)
    x_flow = x_flow.detach()  # 显式切断梯度
    x = torch.concat((x, x_flow.unsqueeze(2)), dim=2)
    
    # Embedding
    tokens = self.embedding(x, dt)
    
    # 纹理调制（可训练）
    tokens = self.backbone(tokens, condition=orbit_embed)
    
    # Decoder
    forecast = self.unembed(tokens)
    
    return forecast
```

这样阶段 2 训练时，梯度完全不会流向 `orbit_flow`，几何能力被"冻结保护"。**这是最安全的渐进训练策略**。

但如果不过度担心（因为 `L_geo` 仍在总损失中），不做 detach 也行——梯度自然会同时优化两个模块，各自从各自的损失项中学习。

## 五、物理约束损失的具体实现

### 5.1 通量守恒（完全独立于几何）

```python
def flux_conservation_loss(pred, source, r_src, r_tgt):
    """
    物理原理：总 EUV 辐通量 ∝ 1/r²
    
    pred:   (B, C, H, W) 模型输出
    source: (B, C, H, W) 输入图像
    r_src:  (B,) 源距离 (km)
    r_tgt:  (B,) 目标距离 (km)
    """
    # 太阳圆面掩码（简单阈值，足够用）
    sun_mask_src = (source > 0.05).float()  # 归一化后的图像
    sun_mask_tgt = (pred > 0.05).float()
    
    # 计算总通量（归一化距离后）
    flux_src = (source * sun_mask_src).sum(dim=(-2, -1))
    flux_tgt = (pred * sun_mask_tgt).sum(dim=(-2, -1))
    
    # 理论通量比
    expected_ratio = (r_src / r_tgt) ** 2
    
    # 实际通量比
    actual_ratio = flux_tgt / (flux_src + 1e-8)
    
    return F.l1_loss(actual_ratio, expected_ratio.unsqueeze(1))
```

### 5.2 临边昏暗约束（独立于几何）

```python
def limb_darkening_gradient_loss(pred):
    """
    物理原理：太阳边缘比中心暗约 30-40%（在 EUV 波段）。
    约束边缘的径向梯度方向和幅度。
    
    pred: (B, C, H, W)
    """
    B, C, H, W = pred.shape
    device = pred.device
    
    # 构建径向坐标
    y, x = torch.meshgrid(
        torch.linspace(-1, 1, H, device=device),
        torch.linspace(-1, 1, W, device=device),
        indexing='ij'
    )
    r = torch.sqrt(x**2 + y**2)  # (H, W)
    
    # 太阳边缘区域：r ∈ [0.75, 0.95]
    edge_mask = ((r > 0.75) & (r < 0.95)).float()
    
    # 计算径向梯度（从中心指向边缘）
    # 对每个像素，梯度应该在边缘区域指向中心（亮度递减）
    dy, dx = torch.gradient(pred, dim=(-2, -1))
    
    # 径向方向（从中心向外）
    radial_dir_y = y / (r + 1e-8)
    radial_dir_x = x / (r + 1e-8)
    
    # 径向梯度（正 = 向外亮度增加，负 = 向外亮度减少）
    radial_grad = dy * radial_dir_y + dx * radial_dir_x  # (B, C, H, W)
    
    # 在边缘区域，亮度应该向外递减（radial_grad < 0）
    # 但同时不能递减太急剧（过度的负梯度意味着人造边缘）
    edge_radial_grad = radial_grad * edge_mask
    
    # 损失 1：梯度应该为负（亮度递减）
    loss_sign = F.relu(edge_radial_grad + 0.01).mean()  # 惩罚正值或零梯度
    
    # 损失 2：梯度幅度合理（不过大不过小）
    loss_magnitude = ((edge_radial_grad + 0.05) ** 2 * edge_mask).mean()
    
    return loss_sign + loss_magnitude
```

### 5.3 结构保持约束（独立于几何）

```python
def structure_preservation_loss(pred, source):
    """
    物理原理：太阳表面的活动区、冕洞等特征结构在视角变化时应保持相对形状。
    使用多尺度结构相似性。
    
    pred:   (B, C, H, W)
    source: (B, C, H, W)
    """
    total_loss = 0.0
    scales = [1, 2, 4]  # 多尺度
    
    for scale in scales:
        if scale > 1:
            pred_s = F.avg_pool2d(pred, scale)
            src_s = F.avg_pool2d(source, scale)
        else:
            pred_s = pred
            src_s = source
        
        # 局部归一化互相关（NCC）
        pred_mean = F.avg_pool2d(pred_s, 7, stride=1, padding=3)
        src_mean = F.avg_pool2d(src_s, 7, stride=1, padding=3)
        
        pred_var = F.avg_pool2d(pred_s**2, 7, stride=1, padding=3) - pred_mean**2
        src_var = F.avg_pool2d(src_s**2, 7, stride=1, padding=3) - src_mean**2
        
        cov = F.avg_pool2d(pred_s * src_s, 7, stride=1, padding=3) - pred_mean * src_mean
        
        # NCC ∈ [-1, 1]，越接近 1 越好
        ncc = cov / (torch.sqrt(pred_var * src_var) + 1e-8)
        
        # 损失：1 - mean(NCC)，鼓励高分
        total_loss += (1.0 - ncc.mean()) / scale  # 粗尺度权重降低
    
    return total_loss
```

## 六、完整的两阶段训练代码

```python
# ============================================================
# train.py — 支持分阶段训练
# ============================================================

def train_phase1_geometry(model, dataloader, epochs=5):
    """
    阶段 1：纯几何缩放训练
    - 仅训练 OrbitFlowModel + Decoder
    - 损失 = MSE(pred, geometric_gt)
    """
    # 冻结设置
    for name, param in model.named_parameters():
        param.requires_grad = False
    
    # 解冻几何相关模块
    for param in model.orbit_flow.parameters():
        param.requires_grad = True
    for param in model.unembed.parameters():
        param.requires_grad = True
    
    optimizer = torch.optim.AdamW(
        filter(lambda p: p.requires_grad, model.parameters()),
        lr=1e-4
    )
    
    for epoch in range(epochs):
        for batch, meta in dataloader:
            pred = model(batch)  # (B, C, H, W)
            gt = batch["forecast"][:, :, 0, :, :]  # (B, C, H, W)
            
            loss_geo = F.mse_loss(pred, gt)
            
            optimizer.zero_grad()
            loss_geo.backward()
            optimizer.step()
            
        print(f"Phase 1 - Epoch {epoch}: geo_loss = {loss_geo.item():.6f}")
    
    return model


def train_phase2_texture(model, dataloader, epochs=10):
    """
    阶段 2：叠加物理纹理约束
    - 在阶段 1 基础上解冻 adaLN + 添加 LoRA
    - 损失 = MSE + λ_flux*L_flux + λ_limb*L_limb + λ_struct*L_struct
    
    ⚠️ 几何模块不被重新训练（使用 detach 或保持冻结）
    """
    # 阶段 1 的几何模块保持冻结
    for param in model.orbit_flow.parameters():
        param.requires_grad = False
    
    # 解冻 adaLN 调制层
    for blk in model.backbone.blocks_attention:
        if blk.adaLN_modulation is not None:
            for param in blk.adaLN_modulation.parameters():
                param.requires_grad = True
    
    # 添加 LoRA 到 Attention 层（使用 PEFT 库）
    from peft import LoraConfig, get_peft_model
    lora_config = LoraConfig(
        r=32, lora_alpha=64,
        target_modules=["qkv", "proj", "fc1", "fc2"],
        lora_dropout=0.1,
    )
    model.backbone = get_peft_model(model.backbone, lora_config)
    
    # Decoder 继续保持可训练
    for param in model.unembed.parameters():
        param.requires_grad = True
    
    optimizer = torch.optim.AdamW(
        filter(lambda p: p.requires_grad, model.parameters()),
        lr=5e-5
    )
    
    # 损失权重
    w_geo = 0.5        # 几何 MSE（防止遗忘）
    w_flux = 0.1       # 通量守恒
    w_limb = 0.05      # 临边昏暗
    w_struct = 0.1     # 结构保持
    
    for epoch in range(epochs):
        for batch, meta in dataloader:
            pred = model(batch)
            source = batch["ts"][:, :, -1, :, :]  # 最后时间步的输入
            gt = batch["forecast"][:, :, 0, :, :]
            
            # 距离信息
            r_src = torch.norm(batch["orbit_params"][:, :3], dim=1) * 149597870.7
            r_tgt = torch.norm(batch["target_orbit_params"][:, :3], dim=1) * 149597870.7
            
            # 计算各项损失
            loss_geo = F.mse_loss(pred, gt)
            loss_flux = flux_conservation_loss(pred, source, r_src, r_tgt)
            loss_limb = limb_darkening_gradient_loss(pred)
            loss_struct = structure_preservation_loss(pred, source)
            
            total_loss = (w_geo * loss_geo + w_flux * loss_flux + 
                         w_limb * loss_limb + w_struct * loss_struct)
            
            optimizer.zero_grad()
            total_loss.backward()
            optimizer.step()
        
        print(f"Phase 2 - Epoch {epoch}: "
              f"total={total_loss.item():.4f}, "
              f"geo={loss_geo.item():.4f}, "
              f"flux={loss_flux.item():.4f}, "
              f"limb={loss_limb.item():.4f}, "
              f"struct={loss_struct.item():.4f}")
    
    return model


# ============================================================
# 主训练入口
# ============================================================
if __name__ == "__main__":
    model = build_orbit_conditioned_model()
    
    # 阶段 1：几何
    model = train_phase1_geometry(model, dataloader, epochs=5)
    torch.save(model.state_dict(), "phase1_geometry.pt")
    
    # 阶段 2：几何 + 纹理（加载阶段 1 权重）
    model.load_state_dict(torch.load("phase1_geometry.pt"))
    model = train_phase2_texture(model, dataloader, epochs=10)
    torch.save(model.state_dict(), "phase2_texture.pt")
```

## 七、总结

| 问题 | 答案 |
|------|------|
| 几何和纹理是否冲突？ | **不冲突**，它们作用于网络的不同深度（像素层 vs 特征层） |
| 先几何后纹理是否可行？ | **完全可行**，且这是推荐的渐进策略 |
| 加纹理时几何会退化吗？ | **不会**，只要保留 `L_geo` 在 loss 中（或 freeze/detach FlowModel） |
| 能否独立调试？ | **可以**，分开训练 → 分别评估 → 确定问题来源 |
| 物理约束是否需要额外数据？ | **不需要**，通量守恒/临边昏暗/结构保持都是无监督损失 |

**建议的实施顺序**：

```
Week 1-2: 实现 OrbitAwareFlowModel + L_geo 训练 → 验证几何缩放正确
Week 3-4: 添加 adaLN 模块框架（先不加物理损失）→ 验证架构不报错
Week 5-6: 逐个添加物理约束损失 → 观察每个约束的效果
Week 7-8: 全损失联合训练 + 超参数调优
```

每个阶段都可以独立测试和验证，不会出现"做到一半发现走不通"的情况。
